Strategy deep-dive #1 — Wall-Mid market making

What is it?

The full Avellaneda–Stoikov formula is beautiful in a paper but loses to something much simpler in practice. Timo's Wall-Mid:

  1. Look at the order book. Find the largest visible wall (concentrated size at one price level).
  2. Place your bid at one tick inside the wall (so you fill before the wall trades).
  3. Place your ask at one tick outside the wall (so you fill when the wall is consumed).
  4. When the wall shifts up or down, your quotes follow.

Why it works

Walls reveal other participants' intent. A 50-unit bid wall at 99.5 means someone wants to buy heavily around 99.5. By sitting one tick inside, you get priority on their fill. When the wall eventually eats, your quote moves outside and you capture the spread on the other side.

This is microstructure-aware market making — no statistical model needed. It's exactly the "1-unit-better pricing" alpha that top teams used.

Code (extracted from Timo's repo, lightly cleaned)

def wall_mid_quotes(book, our_position, max_pos=20):
    """
    book: dict with keys 'bids' and 'asks', each list of (price, volume) sorted
    our_position: int, current inventory (positive = long)
    Returns: (bid_price, ask_price) or (None, None) if no wall
    """
    bids = sorted(book['bids'], key=lambda x: -x[1])  # largest first
    asks = sorted(book['asks'], key=lambda x: -x[1])
    if not bids or not asks:
        return None, None

    bid_wall_price, _ = bids[0]
    ask_wall_price, _ = asks[0]

    # inventory skew: if long, lower both; if short, raise both
    skew = our_position // 5   # one tick of skew per 5 units of inventory
    bid = bid_wall_price + 1 - skew   # 1 tick inside the wall
    ask = ask_wall_price - 1 - skew   # 1 tick outside the wall

    # hard cap
    if our_position >= max_pos:
        bid = None
    elif our_position <= -max_pos:
        ask = None

    return bid, ask

Honest assessment

  • + Dead simple, debuggable, no parameters to fit.
  • + Wins on every round that has visible walls (most P3 rounds do).
  • − Assumes walls are real (not spoofing). On P3 most walls were real, but verify.
  • − No inventory-risk term. Add a hard cap like above; better, add an Avellaneda–Stoikov term as a safety net.

Strategy deep-dive #2 — MACARONS cross-exchange arb

What is it?

P3 Round 4 introduced MAGNIFICENT_MACARONS, a product that traded on TWO archipelago exchanges. The price on each exchange depended on:

  • Sugar price (a public input).
  • Critical Sunlight Index (a public input).
  • Transport cost between islands.
  • Import tariff charged on cross-island trades.

Naïve: trade at the lowest ask across both exchanges. Better: trade with a full factor model and net out transport + tariff.

The Timo heuristic

def macaron_arb_price(external_bid, sugar_idx, transport=1.0, tariff=0.02):
    """
    external_bid: best bid on the OTHER island
    sugar_idx:    normalized sugar & sunlight signal
    Returns: int price to quote on OUR island
    """
    # The famous "round and add 0.5" heuristic
    return int(external_bid + 0.5)

The int(external_bid + 0.5) is the round-and-tick trick: when you see a bid on the other island, you can beat it by one tick after rounding for transport/tariff. The exact coefficients (transport, tariff) were tuned per round; Timo hard-coded them as constants from the round spec.

What to learn from this

Cross-exchange arb in Prosperity is always worth checking. Read the round spec carefully: there will be a transport/tariff section. The trade is straightforward once you net those out.

Strategy deep-dive #3 — ASH/FRUIT Black–Scholes IV smile

What is it?

P3 Round 5 introduced options on the mean-reverting asset ASH (and FRUIT). Timo fit a quadratic implied-vol smile in log-moneyness:

$$\sigma(K) = a + b \cdot \log(K/S)^2$$

Then priced each option using Black–Scholes with that local vol. Coefficients (extracted):

IV_SMILE_COEFFS = {
    "ASH":  [0.27362531, 0.01007566, 0.14876677],
    "FRUIT": [0.20, 0.05, 0.10],   # TBD per spec
}
# σ(K) = a + b * log(K/S) + c * log(K/S)^2

Delta hedge

Once priced, the position is hedged by trading the underlying ASH/FRUIT to neutralize delta:

def hedge_delta(option_position, underlying_position, spot, strike, vol, tau):
    """Compute additional spot position to make total delta = 0."""
    from py_vollib.black_scholes import black_scholes
    from py_vollib.greeks.analytical import delta
    d_opt = delta('c', spot, strike, tau, 0.0, vol) * option_position
    d_total = d_opt + underlying_position
    return -d_total   # trade this much of the underlying

Key insight: Timo hedged in the *underlying* (ASH or FRUIT), not in a futures contract. In Prosperity this matters because the underlying trades actively.

Patterns across all five rounds

  1. Heuristics beat theory on tight-deadline rounds. Wall-Mid, int(bid+0.5), IV smile lookup — all are <50 lines each. Re-deriving Avellaneda–Stoikov from scratch costs time you don't have.
  2. Hard-code the round constants. Transport costs, tariffs, sun indices, market-maker fees — these are spec-given. Don't model them; just plug them in.
  3. Separate the strategy from the harness. Timo's repo cleanly splits "what to trade" from "how to interact with the exchange." When the spec changes, only one layer changes.
  4. Always inventory-cap. Every strategy had a hard inventory limit. Winners didn't blow up on drawdowns.
  5. PnL decomposition matters more than total PnL. Timo's retirements always split: spread capture, inventory drift, rebalance cost. If spread capture is negative, the strategy is broken.

What Timo did NOT do (and what we should)

  • No backtester that reuses past CSVs across rounds. Each round has its own data folder. Reuse scripts you already trust.
  • No deep RL or ML. Everything is rules-based. That's fine for P3 but on P4 (and likely P5) ML edges exist. → module 12
  • No statistical cointegration tests. Catches structural edges that pure market-making misses. → module 05
  • No grid-jump alpha. P4 R5 had a +100 jump edge that moved the 96th team into top 15. → module 16

Reproduce his work

  1. Clone the repo: git clone https://github.com/TimoDiehm/imc-prosperity-3
  2. Pick the strategy you want to understand (e.g., round_1_strategy.py).
  3. Read top-down. The structure is always: __init__ (state) → get_orders (decide) → helper functions.
  4. Trace one tick through by hand using P3 R1 RAINFOREST_RESIN data. Note every assumption.
  5. Re-implement in your own code from scratch. Then diff against Timo's.

By the end of this case study you should be able to (a) explain Wall-Mid to your teammate in 60 seconds, (b) reproduce it on a P3 CSV in <50 lines, and (c) list exactly which P5 rounds it would apply to.
