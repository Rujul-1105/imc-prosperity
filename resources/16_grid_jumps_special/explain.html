Grid Jumps — the plain-English tour

The P4 R5 alpha. Why a discretized GBM is tradeable.

The story

Imagine a temperature gauge. The actual temperature is 72.43°F. The gauge's display only shows whole numbers, so it shows "72". The actual temperature rises slowly to 72.51°F. The display still shows "72". Now the temperature rises to 72.99°F — still "72". Then to 73.00°F — the display jumps to "73".

The jump from 72 to 73 is the "grid jump." It happened because the true temperature crossed an integer boundary. We knew it was about to happen (the true value was 72.99°F; only 0.01 away from 73).

Same idea in financial markets. The true price is something like 99.83. The exchange displays "99" (rounded to integer). The true price rises to 100.17. The display jumps to "100". The 1-tick jump is predictable if you can estimate the true price.

What is a GBM?

Geometric Brownian motion: the price follows dS = σ S dW in continuous time. In tick terms: the price ratio S_{t+1} / S_t is log-normal, with log-volatility σ √Δt.

GBMs are continuous — they can take any real value. But exchanges often display prices on a discrete grid. The grid rounds to the nearest tick. The display is a piecewise-constant function of the true price.

The grid jump

When the true price moves more than the grid size between two ticks, the display jumps. The jump size is one grid unit (could be 1.0, 0.5, 0.1, depending on the round). The jump direction is determined by the sign of the true-price change.

Examples with grid = 1.0:

  • True 100.4 → display 100. True 101.4 → display 101. Jump up by 1.0.
  • True 100.6 → display 101. True 100.4 → display 100. Jump down by 1.0.
  • True 100.4 → display 100. True 100.6 → display 101. Jump up by 1.0 (from 100 to 101).

Notice: even if the display was 100 for several ticks, the true price was wandering inside the (100, 101) range. Eventually it crosses 100.5 and the display jumps.

How to predict the next jump

You don't know the true price directly, but you can estimate it. A simple exponential moving average (EMA) of recent display prices gives a reasonable estimate:

smoothed = α × display_now + (1 − α) × smoothed_before

With a small α (e.g., 0.1), the EMA averages over many recent ticks, smoothing out the jumps. The smoothed value tracks the true price with a lag.

A more sophisticated approach: a Kalman filter, which explicitly models the difference between true price and display. But EMA is good enough for most purposes.

The trade

Compute the smoothed estimate. The "expected next display" is the rounded value:

expected_next = round(smoothed / grid_size) × grid_size

If the current display is more than half a grid below `expected_next`, the display will jump up next tick. Buy.

If the current display is more than half a grid above `expected_next`, the display will jump down next tick. Sell.

Profit per jump: 1 grid size (minus fees).

Why this works in Prosperity but not in real markets

Real markets: a thousand market participants see the same jump, the price moves within the tick. The alpha is competed away to zero. The grid jump edge is for illiquid markets or sandboxed environments where you can predict and act before the crowd.

Prosperity: the exchange is small. Other teams are slow. You can see the jump coming, place the order, get filled. The edge persists.

How the team missed it in P4

Most teams assumed "GBM has no alpha" and skipped the round. Or they used market-making / mean-reversion strategies that don't exploit the grid. Leo Hawking's team noticed the alpha. The result: 96th → top 15 if exploited.

Connection to Prosperity

The grid-jump round appears to be a recurring archetype. P4 R5 had it. P5 will likely have a similar round. Be ready.
