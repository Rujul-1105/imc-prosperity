AR(1) — the discrete-time model

The AR(1) model for a price series $p_t$:

$p_t = c + \beta \cdot p_{t-1} + \varepsilon_t$,   $\varepsilon_t \sim \mathcal{N}(0, \sigma^2_\varepsilon)$

Mean reversion requires $0 < \beta < 1$. When $\beta = 0$, the price is white noise (no memory). When $\beta = 1$, the price is a random walk. When $\beta > 1$, the price is explosive. When $\beta < 0$, the price oscillates.

The long-term mean is:

$\mu = \frac{c}{1 - \beta}$

The "deviation from mean" form (centered AR(1)):

$p_t - \mu = \beta \cdot (p_{t-1} - \mu) + \varepsilon_t$

Variance of the stationary distribution:

$\text{Var}(p_t) = \frac{\sigma^2_\varepsilon}{1 - \beta^2}$

Ornstein–Uhlenbeck — the continuous-time model

Continuous-time equivalent:

$dp_t = \theta \cdot (\mu - p_t)\, dt + \sigma\, dW_t$

Where $\theta$ is the mean-reversion speed, $\mu$ is the long-term mean, $\sigma$ is the vol. The relationship to AR(1) at time step $\Delta t$:

$\beta = e^{-\theta \Delta t}$,   $\sigma^2_\varepsilon = \sigma^2 \cdot \frac{1 - e^{-2\theta \Delta t}}{2\theta}$

For small $\Delta t$ (one tick), $\beta \approx 1 - \theta \Delta t$.

Half-life

The time for a deviation from the mean to shrink by half:

$\tau_{1/2} = \frac{\log(0.5)}{\log(\beta)} = -\frac{\log 2}{\log \beta}$

For $\beta$ close to 1 (slow reversion), this is large. For $\beta$ close to 0 (fast reversion), this is small. A practical rule:

$\beta$Half-life (ticks)Meaning
0.51.0Half-gone next tick. Almost white noise.
0.96.6Moderate reversion.
0.9513.5Slow reversion. ~13 ticks to halve.
0.9968.9Very slow. ~70 ticks to halve.
0.999692Almost a random walk.

Z-score and the strategy

Standardize the price using the fitted mean and standard deviation:

$z_t = \frac{p_t - \mu}{\sigma_p}$

where $\sigma_p = \sqrt{\text{Var}(p_t)} = \sigma_\varepsilon / \sqrt{1 - \beta^2}$ from the AR(1) fit.

The simple z-score strategy:

$z_t > \tau$ (e.g., 2): sell (price is high)
$z_t < -\tau$: buy
$|z_t| < \text{exit}$ (e.g., 0.5): close

Threshold $\tau$ is the entry trigger. Exit at 0 (or near 0) to lock in the reversion. Sizing: linear in z, capped at max position. Bigger $z$ → bigger position.

How to fit AR(1) in Python

import numpy as np
from statsmodels.tsa.ar_model import AutoReg

def fit_ar1(prices):
    """
    Fit AR(1) to a price series. Returns (c, beta, sigma_eps, mu, sigma_p, half_life).
    """
    p = np.asarray(prices, dtype=float)
    model = AutoReg(p, lags=1).fit()
    c = model.params[0]      # constant
    beta = model.params[1]   # AR(1) coefficient
    sigma_eps = np.sqrt(model.sigma2)
    mu = c / (1 - beta) if abs(1 - beta) > 1e-9 else p.mean()
    sigma_p = sigma_eps / np.sqrt(1 - beta**2) if abs(beta) < 1 else sigma_eps
    half_life = -np.log(2) / np.log(beta) if 0 < beta < 1 else np.inf
    return {
        "c": c, "beta": beta, "sigma_eps": sigma_eps,
        "mu": mu, "sigma_p": sigma_p, "half_life": half_life
    }

def zscore(prices, params):
    return (prices[-1] - params["mu"]) / params["sigma_p"]

The strategy in code

def zscore_signal(prices, params, entry=2.0, exit=0.5, max_pos=20):
    """
    Generate a z-score signal and a target position.
    Returns: target_position (signed int)
    """
    z = zscore(prices, params)
    if z > entry:
        return -max_pos   # price is high, sell
    elif z < -entry:
        return +max_pos   # price is low, buy
    elif abs(z) < exit:
        return 0          # close
    else:
        return None       # hold current position (return None to mean "no change")

# Linear-in-z sizing
def zscore_position(z, params, scale=10):
    """Position size scales with |z|. Bigger z = bigger bet."""
    return int(-z * scale)

The Ornstein–Uhlenbeck estimator (continuous-time)

Fit the OU parameters by OLS on the discretized form. Let $\Delta p_t = p_{t+1} - p_t$. The OU model says:

$\Delta p_t = \theta \mu \Delta t - \theta \Delta t \cdot p_t + \sigma \sqrt{\Delta t} \cdot \varepsilon_t$

Regress $\Delta p_t$ on $p_t$ (with intercept). The slope is $-\theta \Delta t$, the intercept is $\theta \mu \Delta t$.

def fit_ou(prices, dt=1.0):
    """Fit OU to a price series via OLS. dt is the time step (in your time units)."""
    p = np.asarray(prices, dtype=float)
    dp = np.diff(p)
    p_lag = p[:-1]
    # dp = a + b * p_lag  => b = -theta * dt
    b, a = np.polyfit(p_lag, dp, 1)
    theta = -b / dt
    mu = a / (theta * dt) if theta != 0 else p.mean()
    residuals = dp - (a + b * p_lag)
    sigma = np.std(residuals) / np.sqrt(dt)
    half_life = np.log(2) / theta if theta > 0 else np.inf
    return {"theta": theta, "mu": mu, "sigma": sigma, "half_life": half_life}

Backtesting a z-score strategy

The walk-forward backtest:

  1. For each tick $t$ after a warm-up period (e.g., 100 ticks):
  2. Fit AR(1) on the past $N$ prices (e.g., $N = 200$, or use expanding window).
  3. Compute z-score. Generate signal.
  4. If signal fires, place order. Track fill (assume fill at touch).
  5. Update inventory and PnL.
  6. Continue.

Decompose PnL: spread capture (entry/exit vs mid), inventory drift (the price you paid for being in the trade), holding cost (opportunity cost of capital).

Key parameter to tune: the entry threshold $\tau$. Sweep over $\{0.5, 1, 1.5, 2, 2.5, 3\}$ and pick the one with best Sharpe. A higher $\tau$ means fewer, larger bets; a lower $\tau$ means more, smaller bets. The optimum depends on the half-life: short half-life → smaller $\tau$ (you can re-enter quickly); long half-life → larger $\tau$ (you want a stronger signal to commit).

When mean reversion works in Prosperity

  • STARFRUIT, ASH, FRUIT — all designed to be mean-reverting. Half-life typically 5-50 ticks.
  • ORCHIDS — fair value driven by external factors, which is itself mean-reverting around the fundamental.
  • Most basket legs — if you regress on a common factor, the residual is mean-reverting.

When mean reversion FAILS

  • Trending series (ROOT, deterministic drift). $\beta$ will be close to 1. Don't trade.
  • GBM with no drift. $\beta = 0$, no memory, no reversion. Trade microstructure edges instead.
  • Regime changes (the parameter shifts mid-round). Re-fit frequently; distrust old parameters.
  • Big jumps. If a single move is more than 5σ, the model is useless. Skip.
